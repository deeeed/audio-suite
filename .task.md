## Package feedback from first integration
- HUD intent must not ellipsize by default; long human intent should wrap, or consumers need documented/configurable HUD rendering.
- Consumers should only need `@farmslot/expo-recipe`; transitive protocol/harness deps should remain package internals for normal CLI use.
- `doctor` should be migration-friendly when repos already have legacy `recipe:run` scripts, or clearly explain that `recipe:run` is reserved by the Expo package.
- Native/live transport docs need a first-class story: Farmslot provides the bridge/HUD scaffold, but app-specific CDP/native probes remain project-owned and should be manifest-versioned.
- CLI/HUD docs should explicitly point to `src/farmslot/RecipeHud.tsx` customization and the 0.1.1 `hud`/`renderHud` config path.
