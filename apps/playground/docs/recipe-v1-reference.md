# AudioLab Recipe v1 reference

AudioLab playground is the Expo/React Native native-module reference
implementation for Farmslot Recipe Protocol v1. The app keeps its existing CDP
bridge; `@farmslot/expo-recipe` adds the dev-only Farmslot bridge/HUD scaffold, and Recipe v1 adds a manifest, portable recipes with per-step `intent`, and standardized summary/trace/artifact output.

## Migration matrix

| Area             | Current evidence                                                                                                                                                                                 | V1 alignment                                                                                                                          | Follow-up                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| App bridge       | `src/agentic-bridge.ts`, `scripts/agentic/cdp-bridge.mjs` expose navigation, state, screenshots, and native audio probes; `src/farmslot/` is generated by `@farmslot/expo-recipe --with-bridge`. | Reused as the project adapter behind Recipe v1 actions, with Farmslot HUD intents routed through the generated dev-only provider.     | Keep bridge probes stable or version them in the manifest.             |
| Official actions | `scripts/agentic/recipe-v1/manifests/audiolab.action-manifest.json` declares `ui.*`, `app.*`, `cdp.target`.                                                                                      | Aligned with Recipe Protocol v1 official vocabulary and manifest metadata shape.                                                      | Add official actions only when the bridge can prove them live.         |
| Domain actions   | Manifest declares `audiolab.audio.*`, `audiolab.native.*`, and `audiolab.asr.*`.                                                                                                                 | Native-module behavior is namespaced and discoverable.                                                                                | Prefer parameterized native probes over one file per task.             |
| Recipes          | `smoke.navigation.recipe.json`, `audio.native.lifecycle.recipe.json`.                                                                                                                            | Recipes use `schema_version: 1`, include required node `intent`, and emit `summary.json`, `trace.json`, and `artifact-manifest.json`. | Add ASR long-run recipes separately when model fixtures are available. |
| Evidence         | Runner writes `.agent/recipe-v1-runs/<timestamp>-<recipe>/`.                                                                                                                                     | Reviewer-facing artifacts are separate from app state.                                                                                | Attach selected artifacts to release/PR evidence.                      |

## Open-source integration example

This branch is intended to be the public, concrete example for integrating an
existing app monorepo with Farmslot Recipe Protocol v1:

1. install the published `@farmslot/expo-recipe` package and keep its generated, versionless scaffold under `scripts/agentic/recipe/` and `src/farmslot/`;
2. wrap the Expo root with `RecipeBridgeProvider` so `app.hud` displays the current human intent when `EXPO_PUBLIC_FARMSLOT_RECIPE_BRIDGE=1`;
3. keep project-specific bridge behavior inside AudioLab (`scripts/agentic/cdp-bridge.mjs`);
4. publish a runner action manifest that separates official actions from namespaced `audiolab.*` actions;
5. author portable recipe JSON under `scripts/agentic/recipe-v1/recipes/`;
6. run recipes through `yarn recipe:v1 ...` to generate the standard v1 evidence package (`recipe.json`, `summary.json`, `trace.json`, `artifact-manifest.json`).

Farmslot can point readers to this repository as a real open-source app that
uses Recipe v1 without moving AudioLab's native probes into Farmslot core.

## Commands

```bash
cd apps/playground
yarn recipe:doctor
yarn recipe:validate
yarn recipe:dry-run
yarn recipe:v1 manifest
yarn recipe:v1 validate scripts/agentic/recipe-v1/recipes/smoke.navigation.recipe.json
yarn recipe:v1 run scripts/agentic/recipe-v1/recipes/smoke.navigation.recipe.json --dry-run
yarn recipe:v1 run scripts/agentic/recipe-v1/recipes/audio.native.lifecycle.recipe.json --device <name>
```

Live runs require an existing development runtime with `globalThis.__AGENTIC__` installed. The playground agentic start/preflight wrappers enable `EXPO_PUBLIC_FARMSLOT_RECIPE_BRIDGE=1` by default so HUD-capable runs also expose `globalThis.__FARMSLOT_RECIPE_BRIDGE__`. Start the app with the normal app commands before running recipes.

## Current validation evidence

Static validation completed on branch `codex/recipe-v1-reference`:

```bash
yarn recipe:doctor
yarn recipe:validate
yarn recipe:dry-run
yarn typecheck
node --check scripts/agentic/recipe-v1/run-recipe-v1.mjs
for f in scripts/agentic/recipe-v1/recipes/*.recipe.json; do
  yarn recipe:v1 validate "$f"
  yarn recipe:v1 run "$f" --dry-run --artifacts-dir ".agent/recipe-v1-runs/dry-run-$(basename "$f" .recipe.json)"
done
```

Dry-run artifacts prove the runner emits the Recipe v1 evidence package shape:
`summary.json`, `trace.json`, and `artifact-manifest.json`.

Live iOS validation was run against `sim:playground-1` after launching the
Playground dev client with `EXPO_PUBLIC_FARMSLOT_RECIPE_BRIDGE=1`:

```bash
yarn recipe:v1 run scripts/agentic/recipe-v1/recipes/smoke.navigation.recipe.json \
  --device sim:playground-1 \
  --artifacts-dir .agent/recipe-v1-runs/live-smoke-navigation-ios

yarn recipe:v1 run scripts/agentic/recipe-v1/recipes/audio.native.lifecycle.recipe.json \
  --device sim:playground-1 \
  --artifacts-dir .agent/recipe-v1-runs/live-native-audio-ios
```

Results:

- `smoke.navigation.recipe.json`: pass, 8/8 nodes.
- `audio.native.lifecycle.recipe.json`: pass, 5/5 nodes.

Native-module recipes must run against a native Android/iOS target; the runner
intentionally rejects `--device web` for `audiolab.native.*` actions so native
proof cannot be satisfied by a browser bridge. Sherpa Voice was also checked as
a downstream recipe consumer: all 14 schemas passed, and the live iOS
`asr-screen-validation.json` smoke passed on `sim:sherpa-voice-1`.

## Farmslot Expo package feedback

This is the first real AudioLab integration of the Expo recipe package. The
main package-level findings are:

- HUD intent text should wrap by default; reviewers need to read the full human
  intent, not an ellipsized one-line summary.
- npm `@farmslot/expo-recipe@0.1.1` includes the configurable compact HUD; consumers can tune the generated `RecipeBridgeProvider` `hud` prop or edit `src/farmslot/RecipeHud.tsx` locally when they need app-specific presentation.
- Normal consumers should only install `@farmslot/expo-recipe`; protocol and
  harness packages should remain transitive/internal for the CLI path.
- `recipe:doctor` is useful, but migration messaging should be clearer when a
  repo already owns a legacy `recipe:run` script.
- Native app docs should make the boundary explicit: Farmslot owns the
  scaffold/HUD/protocol, while app-specific CDP/native probes stay in the app
  and are declared in the manifest.
